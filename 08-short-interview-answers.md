# 08. Manual Testing Short Interview Answers

## 1. What is Manual Testing?
Manual testing is checking software manually to verify whether the actual behavior matches the expected behavior and to find defects.

## 2. Why is Manual Testing important?
It is important because it validates user experience, exploratory scenarios, visual behavior, and business flows that automation may not cover effectively.

## 3. What is SDLC?
SDLC is the full software development lifecycle from requirement gathering to deployment and maintenance.

## 4. What is STLC?
STLC is the testing lifecycle that includes requirement analysis, test planning, execution, defect tracking, and closure.

## 5. Difference between Waterfall and Agile?
Waterfall is sequential and rigid, while Agile is iterative and flexible to changing requirements.

## 6. What is V-Model?
V-model pairs each development stage with a testing stage to detect defects early.

## 7. What is a test case?
A test case is a detailed set of steps, inputs, and expected results used to validate a feature.

## 8. What is a test scenario?
A test scenario is a high-level business flow that needs to be tested.

## 9. What is positive testing?
Positive testing checks whether valid inputs produce the expected result.

## 10. What is negative testing?
Negative testing checks whether invalid inputs are handled correctly and reject unwanted behavior.

## 11. What is boundary value analysis?
Boundary value analysis tests values at the edge of valid and invalid ranges.

## 12. What is equivalence partitioning?
Equivalence partitioning groups inputs into similar behavior classes to reduce repeated test cases.

## 13. What is smoke testing?
Smoke testing is a quick check of critical functions to confirm the build is stable enough for further testing.

## 14. What is sanity testing?
Sanity testing is a focused validation of a small change or bug fix.

## 15. What is regression testing?
Regression testing ensures that recent changes did not break existing functionality.

## 16. What is retest?
Retest confirms whether a previously reported bug has been fixed.

## 17. What is exploratory testing?
Exploratory testing is testing while learning and discovering issues simultaneously without a fixed script.

## 18. What is UAT?
UAT is done by end users or business stakeholders to confirm the application meets business requirements before release.

## 19. What is a defect?
A defect is a mismatch between expected behavior and actual behavior.

## 20. What is severity?
Severity tells how serious the defect is in terms of system or business impact.

## 21. What is priority?
Priority tells how urgently the defect should be fixed.

## 22. Difference between severity and priority?
Severity is about impact; priority is about urgency.

## 23. What is a bug report?
A bug report is a formal record of a defect with reproduction steps, expected result, actual result, and evidence.

## 24. What is functional testing?
Functional testing checks whether the application behaves according to business requirements.

## 25. What is non-functional testing?
Non-functional testing checks performance, security, usability, and reliability.

## 26. What is compatibility testing?
Compatibility testing checks whether the application works in different browsers, OS, and devices.

## 27. What is security testing?
Security testing checks whether the app is protected from unauthorized access and vulnerabilities.

## 28. What is performance testing?
Performance testing measures how the system behaves under expected or heavy load conditions.

## 29. Why do we need defect tracking?
Defect tracking helps teams monitor issue status, assign ownership, and ensure bugs are resolved before release.

## 30. What is the main goal of testing?
The goal of testing is to find defects early, reduce risk, and ensure the product meets user and business needs.

---

## Final 2-Line Interview Answer

Manual testing is the process of validating software manually to compare actual behavior with expected behavior and identify defects before release. A good tester understands requirements, writes effective test cases, performs smoke, regression, and exploratory checks, and reports defects clearly with proper severity and priority.
